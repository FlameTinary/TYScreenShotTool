# Sprint 23 - 截图动作扩展

## Status

Completed

## Goal

在现有截图编辑工作流基础上，
补齐两个最小动作入口：

- OCR
- Pin

本次目标是：

让用户在框选进入截图编辑态后，
可以通过工具栏主动触发 OCR 或 Pin，
继续保持“截图结果由用户手动触发后续动作”的统一工作流。

---

## Scope

### Included

- 在工具栏中增加 OCR 入口
- 在工具栏中增加 Pin 入口
- 保持现有复制、保存、取消工作流不被破坏
- 保持工具栏态统一的手动触发式操作路径

### Out of Scope

- 修改长截图
- 修改 AI 分析
- 调整现有 PNG 保存链路
- 调整现有 Clipboard 链路
- 调整现有标注、圆角、阴影、马赛克与区域微调交互

---

## Implementation

### 已实现

1. 在现有底部工具栏结构上增加 `OCR` 与 `Pin` 入口
2. 不改现有截图状态机
3. `OCR` 改为编辑态手动触发
4. `OCR` 识别基于原始冻结截图选区，不携带矩形、圆形、箭头等编辑内容
5. `OCR` 成功后：
   - 输出 `OCR Success`
   - 输出 `text: ...`
   - 将识别结果复制到剪贴板
   - 结束当前编辑态
6. `Pin` 基于当前截图结果生成单实例浮动窗口
7. `Pin` 成功后关闭当前 Overlay，结束本次截图会话
8. 保持复制、保存、取消与现有标注主链路正常

### 约束落实

- 遵循 MVP
- 遵循 KISS
- 遵循 YAGNI
- 不新增复杂动作调度层
- 不提前实现长截图 / AI 分析

---

## Validation

### 场景 1

框选进入截图编辑态后，
工具栏中应出现 OCR 入口。

### 场景 2

框选进入截图编辑态后，
工具栏中应出现 Pin 入口。

### 场景 3

点击 `OCR` 后，
应输出识别结果到 `Console`，
将识别文本复制到剪贴板，
并结束当前编辑态。

### 场景 4

点击 `OCR` 时，
识别内容应仅来自原始截图区域，
不携带矩形、圆形、箭头等编辑内容。

### 场景 5

点击 `Pin` 后，
应进入最小可用 `Pin` 链路。

### 场景 6

复制、保存、取消与现有标注主链路应保持正常。
