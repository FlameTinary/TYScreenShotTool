# Sprint 27 - 设置页 OCR 开关移除

## Status

Completed

## Goal

在不影响编辑界面 `OCR` 主链路的前提下，
从设置页面移除 `OCR` 开关，
让设置项与当前真实产品行为保持一致。

---

## Scope

### Included

- 从设置界面移除 `OCR 开关` UI
- 移除设置页 `OCR 开关` 对应的无效本地配置
- 保持编辑界面 `OCR` 工具栏入口与识别流程正常
- 更新与该设置项相关的当前文档描述

### Out of Scope

- 修改编辑界面 `OCR` 的触发方式
- 修改 `OCRService` 识别逻辑
- 新增 `OCR` 高级设置
- 修改 `AI 分析` 相关规划

---

## Implementation

### 方向

优先采用最小改动：

1. 只移除设置页中已经失效的 `OCR` 开关
2. 不调整编辑界面的 `OCR` 按钮与识别服务
3. 同步清理对应无效配置常量与文档描述

### 实际完成

1. 从 `Settings` 页面移除了 `OCR 开关`
2. 删除了设置页 `OCR` 开关对应的无效本地配置常量
3. 保持编辑界面 `OCR` 工具栏入口与识别链路不变
4. 同步修正 `README`、`PROJECT_CONTEXT`、`TASK` 与 `ROADMAP` 中的当前描述

### 约束

- 遵循 MVP
- 遵循 KISS
- 遵循 YAGNI
- 不借此重构设置模块

---

## Validation

### 场景 1

打开 `Settings` 页面后，
不再显示 `OCR 开关`。

### 场景 2

设置页面中的 `HotKey 配置` 与 `保存目录配置` 仍正常显示和使用。

### 场景 3

在编辑界面点击 `OCR` 按钮后，
仍可正常执行识别、输出结果并复制文本。

### 场景 4

现有截图、复制、保存、`Pin`、长截图主链路保持正常。

---

## Result

Completed

- `Settings` 页面已不再显示 `OCR 开关`
- 编辑界面 `OCR` 入口保持正常可用
- `HotKey` 与保存目录设置未受影响
- 当前设置页能力与真实产品行为重新对齐
