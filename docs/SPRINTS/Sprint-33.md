# Sprint 33 - 自定义截图热键

## Status

Done

## Goal

在现有 `Settings` 页面中，
将“截图快捷键”从少量预设菜单，
升级为最小可用的自定义热键输入体验。

用户应能够：

`点击编辑框 -> 输入热键组合 -> 按回车确认 -> 立即生效`

同时在取消或失败时，
应用必须恢复旧热键并保持当前截图入口继续可用。

---

## Scope

### Included

- 将 `Settings` 页面中的截图快捷键配置从预设菜单改为可点击编辑框
- 点击编辑框后进入热键编辑模式
- 支持录入 `Command / Shift / Option / Control` 与 `字母 / 数字 / 功能键 / 方向键` 组合
- 用户按 `Return` 后确认热键并立即尝试注册
- 用户按 `Esc` 或点击编辑框外部后取消编辑并恢复旧热键
- 注册失败时恢复旧热键并给出明确提示
- 保存目录配置与其他现有设置页行为保持正常

### Out of Scope

- 快捷键冲突详情列表
- 多个截图动作分别配置热键
- 单独的热键录制弹窗
- 鼠标按键或手势热键
- 历史热键记录

---

## Implementation

### 方向

优先采用最小原生实现：

1. `SettingsView` 继续保留 SwiftUI 页面结构
2. 新增一个桥接 AppKit 的热键录制控件负责输入捕获
3. `ScreenshotHotKey` 从预设集合扩展为真实热键模型
4. 继续复用 `GlobalHotKeyService.updateHotKey(...)` 做注册与失败回退

### 约束

- 遵循 MVP
- 遵循 KISS
- 遵循 YAGNI
- 不重做当前全局热键注册机制
- 不新增第二层设置页或热键弹窗
- 不影响保存目录设置与截图主链路

---

## Validation

### 场景 1

进入 `Settings` 页面后，
“截图快捷键”显示为可点击编辑框，
而不是预设菜单。

### 场景 2

点击编辑框后，
进入热键编辑模式。

### 场景 3

用户输入 `Command + A` 时，
编辑框可实时显示该组合。

### 场景 4

用户输入 `Command + Shift + 8`、
`Control + Option + F5`、
`Command + ↑` 等组合时，
编辑框可正确显示。

### 场景 5

用户只按修饰键时，
不能直接确认为有效热键。

### 场景 6

用户按 `Return` 后，
若组合有效且注册成功，
新热键立即生效。

### 场景 7

用户按 `Return` 后，
若注册失败，
界面恢复旧热键并给出失败提示。

### 场景 8

用户按 `Esc` 或点击编辑框外部后，
会取消编辑并恢复旧热键。

### 场景 9

保存目录配置与其他现有设置页行为保持正常。

## Result

- `Settings` 页面中的截图快捷键配置已从预设菜单改为可点击编辑框
- 用户点击编辑框后可直接录入热键组合，并在录制态看到浅蓝高亮反馈
- 支持 `Command / Shift / Option / Control` 与 `字母 / 数字 / 功能键 / 方向键` 组合输入
- 用户按 `Return` 后，若组合有效且注册成功，新热键会立即生效
- 用户只按修饰键时不会保存为有效热键，并会收到“请至少输入一个主键”提示
- 注册失败时会恢复旧热键，并提示“快捷键注册失败，请更换组合”
- 用户按 `Esc` 或点击编辑框外部后，会取消编辑、退出高亮并恢复旧热键
- 重新打开 `Settings` 后，热键编辑高亮与错误提示不会残留
- 保持保存目录配置与现有截图主链路正常
