# Sprint 32 - 长截图 OCR / AI

## Status

Done

## Goal

在现有长截图模式基础上，
补齐最小 `OCR` 与 `AI 分析` 入口，
让用户在滚动拼接过程中，
可以直接基于当前已经生成的长图结果执行文本识别与 AI 分析，
而不需要先退出长截图模式。

本次目标不是重做长截图预览结构，
也不是新增长截图专用结果窗口体系，
而是先补齐长截图模式中的最小分析能力闭环。

---

## Scope

### Included

- 长截图底部操作面板增加 `OCR` 与 `AI` 两个入口
- `OCR` 与 `AI` 基于当前已经拼接出的长图结果执行
- 进入 `OCR` 或 `AI` 后不结束长截图会话
- 关闭结果窗后允许用户继续滚动追加长截图
- 长截图模式下同一时刻只保留一个结果窗
- `OCR` 与 `AI` 结果窗位置根据长截图预览窗所在侧反向摆放
- 当目标侧空间不足时，结果窗回退到安全可见布局

### Out of Scope

- 长截图模式下的标注能力扩展
- 长截图专用 `OCR` / `AI` 结果窗重写
- 多结果窗并存
- AI 请求取消机制重构
- 长截图历史结果归档
- AI 结果与长图结果联动标记

---

## Implementation

### 方向

优先采用最小复用实现：

1. 扩展现有长截图底部操作面板，而不是新增第二套工具栏
2. `OCR` 与 `AI` 继续复用现有预览窗口服务
3. 长截图预览窗口只补充“当前位于左侧还是右侧”的定位信息
4. 结果窗优先摆放在长截图预览窗的对侧，减少互相遮挡
5. 任何分析动作都基于当前已生成的长图，不打断长截图会话

### 约束

- 遵循 MVP
- 遵循 KISS
- 遵循 YAGNI
- 不修改普通截图编辑态的现有入口与行为
- 不改变当前长截图滚轮驱动追加主链路
- 不引入新的设置项

---

## Validation

### 场景 1

进入长截图模式后，
底部操作面板可见：

`取消 / OCR / AI / 保存 / 复制`

### 场景 2

长截图模式刚进入时，
即使用户还未继续滚动，
也可以基于首帧长图执行 `OCR` 与 `AI`。

### 场景 3

点击 `OCR` 后，
会基于当前长图结果展示 `OCR` 预览窗口，
关闭窗口后仍可继续滚动追加长截图。

### 场景 4

点击 `AI` 后，
会基于当前长图结果展示 `AI` loading / 结果 / 失败状态，
关闭窗口后仍可继续滚动追加长截图。

### 场景 5

当长截图预览窗位于左侧时，
`OCR` / `AI` 结果窗优先出现在右侧；
当长截图预览窗位于右侧时，
`OCR` / `AI` 结果窗优先出现在左侧。

### 场景 6

当 `OCR` 结果窗已打开时点击 `AI`，
旧 `OCR` 窗口会自动关闭；
当 `AI` 窗口已打开时点击 `OCR`，
旧 `AI` 窗口会自动关闭。

### 场景 7

`AI` loading 中切换到 `OCR` 后，
旧的 `AI` 异步结果不会重新弹出覆盖当前界面。

### 场景 8

长截图模式下的 `保存 / 复制 / 取消 / 继续滚动追加` 主链路保持正常。

---

## Result

### 实现结果

- 长截图底部操作面板已扩展为 `取消 / OCR / AI / 保存 / 复制`
- 长截图模式下可直接基于当前长图结果执行 `OCR` 与 `AI`
- 首帧长图在未继续滚动时也可直接触发 `OCR` 与 `AI`
- `OCR` 与 `AI` 结果窗会根据长截图预览窗所在侧反向摆放
- 长截图模式下同一时刻只保留一个结果窗
- 从 `AI` 切到 `OCR`、继续滚动、取消、保存、复制或结束会话时，旧 `AI` 异步结果都会失效，不再晚到重弹
- `OCR` / `AI` 结果窗关闭后不会结束长截图会话，用户仍可继续滚动追加
- `AI` 分析窗口在屏幕空间不足时，底部按钮会自动换行，不再显示不全
