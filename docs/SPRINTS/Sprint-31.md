# Sprint 31 - 窗口悬停选择

## Status

Completed

## Goal

在现有自由拖拽框选截图流程的基础上，
增加一个最小 `窗口悬停选择` 起手体验，
让用户在需要截取整个应用窗口时，
可以通过：

`悬停窗口 -> 点击确认`

直接进入现有截图编辑态。

本次目标不是实现窗口内部区域识别，
也不是重做当前截图编辑架构，
而是先补齐“整窗截图更轻量”的第一步体验。

---

## Scope

### Included

- 热键触发后，Overlay 保持统一选择模式
- 鼠标移动到可识别应用窗口上方时，显示与窗口边界一致的候选高亮框
- 候选区域内部遮罩变为透明，视觉尽量复用当前选区风格
- 鼠标移动到其他窗口时，候选高亮随之切换
- 用户轻点鼠标左键时，确认当前候选窗口并进入现有编辑态
- 用户按下鼠标后开始拖拽时，立即切回现有自由框选流程
- 鼠标位于桌面空白区域或无法识别有效窗口时，回退为当前普通待命状态

### Out of Scope

- 窗口内部子区域识别
- 自动识别按钮、面板、代码编辑区
- 新的截图模式切换 UI
- 新的设置页开关
- OCR / AI / Pin / 长截图能力扩展
- 编辑态能力扩展

---

## Implementation

### 方向

优先采用最小实现：

1. 保持当前热键触发与 Overlay 主入口不变
2. 在当前选择阶段内增加“候选窗口预览”能力，而不是新增复杂会话状态
3. 点击确认窗口后，继续复用现有编辑态入口
4. 任何窗口命中失败场景，都回退为当前自由框选待命，不阻断主链路

### 约束

- 遵循 MVP
- 遵循 KISS
- 遵循 YAGNI
- 只支持整个应用窗口
- 不引入新的系统权限前提
- 不破坏当前自由框选主链路

---

## Validation

### 场景 1

热键触发截图后，
鼠标移动到普通应用窗口上方时，
可看到与窗口边界一致的候选高亮框。

### 场景 2

鼠标继续移动到其他窗口时，
候选高亮会跟随切换到新的窗口。

### 场景 3

鼠标位于桌面空白区域时，
不显示候选窗口高亮，
Overlay 保持普通待命状态。

### 场景 4

当存在候选窗口时，
用户轻点鼠标左键，
应用直接以该窗口矩形进入现有编辑态。

### 场景 5

当用户按下鼠标后开始拖拽时，
应用会放弃候选窗口，
并按现有自由框选流程运行。

### 场景 6

通过窗口悬停确认进入编辑态后，
复制、保存、`OCR`、`AI`、`Pin`、长截图主链路保持正常。

Completed

- 已支持热键触发后的窗口悬停候选高亮
- 已支持点击候选窗口直接进入现有编辑态
