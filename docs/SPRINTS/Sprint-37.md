# Sprint 37 - 界面结构识别

## Status

Done

## Goal

在 Sprint 35 已完成 `AI` 菜单与 `摘要总结`、
Sprint 36 已完成 `翻译语言` 的基础上，
继续为当前 `AI` 菜单扩展新的实用方向：

- `界面结构识别`

本轮先支持：

- 网页界面元素
- App 界面元素

但先按通用结构输出，
不做平台分流。

本轮必须同时覆盖：

- 普通截图编辑模式
- 长截图模式

同时保持：

- Sprint 34 的本地 OCR / 视觉取字双输入链路不变
- 当前 `AI` 结果窗容器继续复用
- 长截图现有结果窗摆放规则与异步失效保护不变

---

## Scope

### Included

- 在普通截图 `AI` 菜单中新增一级项 `界面结构识别`
- 在长截图 `AI` 菜单中新增一级项 `界面结构识别`
- 网页与 App 截图都可使用该能力
- 继续复用 Sprint 34 的双输入链路
- 输出单段结构化文本
- 结构化文本固定覆盖：
  - `组件识别`
  - `结构层级`
  - `视觉特征`
  - `交互语义`
  - `实现提示`
- `实现提示` 采用混合风格：
  - 先给通用实现描述
  - 再补一句前端 / 原生都可参考的实现方向
- 继续复用当前 `AI` 结果窗
- 支持 `复制全部` 与 `复制结构`
- 保持普通截图与长截图现有重试语义
- 保持长截图结果窗摆放与异步失效保护

### Out of Scope

- 直接生成 `HTML/CSS`
- 直接生成 `SwiftUI` / `AppKit` 代码
- Figma 组件映射
- Web / App 分平台菜单入口
- Web / App 分平台结果窗
- JSON 风格结果输出
- 新增设置页开关
- 独立 `UI` 分析窗口

---

## Implementation

### 方向

优先采用最小一级菜单扩展实现：

1. 在现有 `AI` 菜单中增加一级项 `界面结构识别`
2. 在 `AIAnalysisMode` 中加入新的界面结构识别方向
3. 继续复用当前双输入取字链路
4. 继续复用 `AIAnalysisService`，为该方向增加单段结构化描述输出
5. 继续复用当前 `AI` 结果窗，以单段结构化文本形式展示结果

### 约束

- 遵循 MVP
- 遵循 KISS
- 遵循 YAGNI
- 不新增第二种 `AI` 结果窗口
- 不新增新的 Settings 配置项
- 不影响保存、复制、`OCR`、`Pin`、长截图主链路

---

## Validation

### 场景 1

普通截图点击 `AI` 后，
可以看到一级菜单项 `界面结构识别`。

### 场景 2

长截图点击 `AI` 后，
也可以看到一级菜单项 `界面结构识别`。

### 场景 3

选择 `界面结构识别` 后，
结果窗继续复用当前 `AI` 结果窗容器。

### 场景 4

结果窗只展示一段结构化文本，
而不是新的多段窗口。

### 场景 5

结构化文本中固定包含：

- `组件识别`
- `结构层级`
- `视觉特征`
- `交互语义`
- `实现提示`

### 场景 6

点击 `复制结构` 后，
能够复制完整结构化文本，
并且只关闭结果窗，
不退出当前模式。

### 场景 7

开关关闭时，
能力继续走本地 OCR 链路。

### 场景 8

开关打开时，
能力继续走视觉取字链路。

### 场景 9

无有效内容时，
只提示 `AI 未识别到有效内容`，
不保留结果窗。

### 场景 10

失败时，
提示 `AI 分析失败`，
并支持重试。

### 场景 11

重试时保持原分析方向，
不重新弹菜单。

### 场景 12

长截图中结果窗继续遵守当前左右摆放规则与异步过期保护。

---

## Result

Sprint 37 完成后，普通截图与长截图中的 `AI` 菜单都已支持一级项 `界面结构识别`；该方向继续复用 Sprint 34 的本地 OCR / 视觉取字双输入链路，结果继续复用现有 `AI` 结果窗，并支持 `复制全部` 与 `复制结构` 两种复制语义。

本轮实现过程中还补齐了两个关键收口点：

- 界面结构识别结果被固定约束为 `组件识别 / 结构层级 / 视觉特征 / 交互语义 / 实现提示` 五个小标题，不再只是宽泛的单段自由输出
- 当 AI 返回为空、结构不完整或缺少固定小标题时，普通截图与长截图都会统一提示 `AI 未识别到有效内容`，不再误落到通用 `AI 分析失败`
