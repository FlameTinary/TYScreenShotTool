## Goal

让截图编辑态中的马赛克预览效果与最终导出结果保持一致，
并允许用户在编辑态中继续微调马赛克区域。

当前问题是：
截图过程中，马赛克区域只表现为一层偏浅的临时遮罩；
且用户完成马赛克框选后，无法像调整截图区域那样继续移动或缩放马赛克区域。

本次目标是：
在不破坏现有截图交互的前提下，
让编辑态与最终导出都使用 `CIGaussianBlur` 呈现毛玻璃马赛克，
并支持对马赛克区域进行拖动与缩放微调，
同时避免引入拖拽完成后的闪屏副作用。

## Scope

### Included

- 调整截图编辑态中的马赛克预览表现
- 让编辑态与最终导出都使用 `CIGaussianBlur` 呈现毛玻璃马赛克
- 保持现有马赛克工具的绘制入口与创建方式不变
- 支持鼠标进入马赛克区域时显示手型
- 支持拖动已有马赛克区域
- 支持在马赛克区域边缘与角上缩放马赛克区域
- 保持复制、保存导出的马赛克结果不回退
- 保持截图拖拽完成后不出现新的明显闪屏
- 保持 `SelectionCompleted` 后的截图区域仍然是现有 Overlay/选区编辑模型

### Out of Scope

- 新增马赛克强度滑块
- 新增多种马赛克样式
- 修改矩形、圆形、箭头、画笔、文字的交互方式
- 修改 OCR / Pin / 长截图 / AI
- 为未来预留新的渲染框架或抽象层
- 将 `SelectionCompleted` 后的选区替换为真实截图图片内容

## Implementation

### 方向

优先采用最小实现：

1. 不改导出侧现有马赛克算法
2. 不改截图完成后进入工具栏态的交互节奏
3. 不通过隐藏整个 overlay 再抓图的方式刷新预览
4. `SelectionCompleted` 后禁止将截图区域替换为真实截图图片内容
5. 马赛克区域的拖动与缩放应尽量复用现有截图区域交互模型
6. 如果预览无法做到与最终结果完全一致，优先保证“视觉方向一致且不闪屏”

### 约束

- 遵循 MVP
- 遵循 KISS
- 遵循 YAGNI
- 不新增设置项
- 不新增 Protocol
- 不新增导出流程层

### 实现结果

- 编辑态马赛克预览改为基于 `CIGaussianBlur` 的局部毛玻璃效果
- 导出 PNG 与复制结果继续使用 `CIGaussianBlur`，与编辑态保持一致方向
- 马赛克区域支持在编辑态中继续拖动与缩放
- 为兼容新版 macOS SDK，预览态底图改为基于 `ScreenCaptureKit` 的整屏抓取

### Bug Fix

#### 马赛克保存时崩溃

问题：

- 在截图编辑态添加马赛克后点击保存，应用崩溃
- Xcode 控制台输出 `NSGenericException`
- 调用栈定位到 `CaptureAnnotationCanvasView.cursorUpdate(with:)`

原因：

- 马赛克 hover 更新过程中，在 `cursorUpdate` 回调里再次调用了 `invalidateCursorRects`
- AppKit 重复触发 Window Structural Regions 更新，最终抛出异常

修复：

- 移除马赛克 hover 过程中的 `invalidateCursorRects` 递归调用
- 改为直接根据当前命中状态设置光标
- 保留拖动与缩放交互，不再走会触发递归更新的光标刷新路径

结果：

- 点击保存不再触发崩溃
- 马赛克编辑态保持稳定

#### 马赛克光标反馈异常

问题：

- 鼠标进入马赛克内部时，未按下鼠标前仍显示十字
- 鼠标移动到马赛克边缘与角时，未按下鼠标前不显示双向箭头
- 只有开始拖动后才显示正确光标

原因：

- `CaptureAnnotationCanvasView` 已正确计算手型与缩放光标
- 但外层 `CaptureOverlayView` 在预览态持续将截图区域内光标重置为十字
- 导致 canvas 设置的光标被覆盖

修复：

- 当当前正在使用标注工具且鼠标位于截图选区内时，停止由 `CaptureOverlayView` 接管光标
- 改由 `CaptureAnnotationCanvasView` 独立管理马赛克的 hover / move / resize 光标

结果：

- 鼠标进入马赛克内部时可直接显示手型
- 鼠标进入马赛克边缘与角时可直接显示对应双向箭头
- 拖动与缩放反馈与实际交互保持一致
