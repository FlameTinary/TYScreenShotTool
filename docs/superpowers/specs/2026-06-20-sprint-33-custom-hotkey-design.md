# Sprint 33 - 自定义截图热键设计文档

## 目标

在现有 `Settings` 页面中，
将“截图快捷键”从少量预设选项，
升级为最小可用的自定义热键输入体验。

第一版能力明确收敛为：

`点击编辑框 -> 进入热键编辑模式 -> 键盘输入组合 -> 回车确认 -> 立即生效`

同时支持：

- `Esc` 取消本次编辑
- 点击编辑框外部取消本次编辑
- 注册失败时恢复旧热键并给出明确提示

本轮不重做全局热键注册机制，
也不扩展到截图快捷键以外的其他动作。

---

## 背景

当前项目已经具备：

- 全局截图热键注册
- `Settings` 页面
- 热键配置持久化
- 修改后立即更新全局热键

但当前“截图快捷键”配置仍然是预设菜单：

- `⌘⇧2`
- `⌘⇧8`
- `⌘⇧9`

这意味着用户无法输入自己习惯的组合，
只能在少量预设中选择。

对于截图工具而言，
热键是高频入口，
比继续增加更多预设更有价值的提升，
是让用户直接录入自己的组合。

对当前阶段最合适的做法，
不是引入复杂的热键管理面板，
而是在现有 `Settings` 页面中补齐一个最小热键录制控件。

---

## 目标用户

核心用户：

- 单人开发者
- 已有自己热键习惯的用户
- 希望截图快捷键能立即改为常用组合的用户

本轮不面向以下场景：

- 多套快捷键方案切换
- 不同截图动作配置不同热键
- 快捷键冲突分析面板
- 复杂的热键历史与恢复机制

---

## 需求

### 功能需求

1. 用户在 `Settings` 页面点击“截图快捷键”编辑框后，进入热键编辑模式。
2. 处于编辑模式时，编辑框应响应键盘输入，并实时显示当前输入组合。
3. 支持的组合范围为：
   - 修饰键：`Command`、`Shift`、`Option`、`Control`
   - 主键：字母、数字、功能键、方向键
4. 不允许“只有修饰键，没有主键”的组合。
5. 用户按 `Return` 时，若当前组合有效，则确认该热键并立即尝试注册。
6. 注册成功后，新热键应立即生效并写入设置。
7. 若注册失败，应恢复旧热键并给出明确提示。
8. 用户按 `Esc` 时，应取消本次编辑并恢复旧热键。
9. 用户点击编辑框外部区域时，应取消本次编辑并恢复旧热键。

### 非功能需求

1. 保持实现简单、原生、可维护。
2. 不引入额外弹窗或第二层设置界面。
3. 不修改现有全局热键注册底层机制，只复用当前更新能力。
4. 不影响当前截图主链路与现有设置页保存目录配置。
5. 不为了未来多动作热键系统提前抽象复杂结构。

---

## 方案比较

### 方案 A：继续用纯 SwiftUI 输入控件处理热键录制

优点：

- 设置页表层代码看起来更集中
- 不需要桥接 AppKit 视图

缺点：

- macOS 下对修饰键、方向键、功能键、`Esc`、`Return`、失焦取消的捕获不够直接
- 很容易在焦点和键盘事件处理上堆积例外逻辑
- 对桌面级快捷键录制体验不够稳

### 方案 B：用 `NSViewRepresentable` 包一层 AppKit 热键录制输入框

优点：

- 更符合 macOS 桌面输入控件能力边界
- 更容易稳定处理修饰键组合、主键确认、`Esc` 取消、失焦取消
- 可以把“输入捕获”和“全局热键注册”明确拆开
- 与当前项目“原生优先、简单可维护”的方向一致

缺点：

- 相比纯 SwiftUI 多一个桥接输入控件
- 需要补一小层输入状态同步

### 方案 C：保留当前预设菜单，再增加单独的“录制热键”弹窗

优点：

- 逻辑可以独立在弹窗内封装
- 体验模式和很多桌面工具相似

缺点：

- 对当前需求来说偏重
- 用户只是改一个快捷键，却需要进入第二层界面
- 不符合本项目 MVP 优先的收敛方向

### 推荐方案

选择方案 B。

这是当前最小、最稳、最符合 macOS 原生实现路径的方案。

它可以直接验证核心假设：

`用户是否会更愿意在 Settings 中直接录入自己习惯的截图热键，而不是从固定预设中挑选。`

---

## 设计方案

### 1. 交互入口

将当前 `Settings` 页面中的“截图快捷键”配置，
从预设 `Picker`，
替换为一个可点击聚焦的热键编辑框。

默认态下：

- 编辑框显示当前已生效热键
- 用户可以点击进入编辑模式

本轮不保留“预设菜单 + 自定义热键”双入口，
而是直接统一为自定义输入体验。

### 2. 编辑模式

当用户点击编辑框后，
控件进入热键编辑模式。

进入时应执行：

- 记录当前旧热键，作为取消或失败时的回退值
- 让编辑框获取焦点
- 展示“正在录制热键”的输入态

此时用户的键盘输入不再是普通文本输入，
而是按键组合捕获。

### 3. 可输入组合范围

本轮支持以下修饰键：

- `Command`
- `Shift`
- `Option`
- `Control`

本轮支持以下主键：

- 字母键
- 数字键
- 功能键
- 方向键

组合规则：

- 可以是任意修饰键组合 + 一个主键
- 不能只有修饰键，没有主键
- 当用户只按下修饰键时，可以更新当前显示，但不能直接确认成功

### 4. 确认、取消与失焦

当编辑框中已经形成有效候选组合后：

- 用户按 `Return`
  - 尝试注册该热键
  - 成功则写入设置并退出编辑模式
  - 失败则恢复旧热键并提示失败

- 用户按 `Esc`
  - 放弃本次编辑
  - 恢复旧热键
  - 退出编辑模式

- 用户点击编辑框外部
  - 视为取消本次编辑
  - 恢复旧热键
  - 退出编辑模式

如果用户输入后的组合与旧值完全相同，
则按 `Return` 时直接退出编辑模式，
不重复注册。

### 5. 注册失败处理

本轮明确采用“先显示候选值，确认失败再回退”的规则。

也就是说：

- 用户录制时，编辑框可以先显示新组合
- 只有按 `Return` 后才视为正式提交
- 如果调用现有全局热键更新逻辑失败：
  - 恢复旧热键显示
  - 保持旧热键继续生效
  - 给出明确失败提示

这样可以保证：

- 用户不会因为一次失败输入丢失当前可用热键
- 应用不会停留在“界面显示新值，但系统实际未生效”的不一致状态

### 6. 职责划分

建议职责边界如下：

- `SettingsView`
  - 负责展示设置项
  - 管理热键编辑中的界面状态与错误提示
  - 接收热键录制结果并发起更新

- 新增热键录制控件（建议为独立小组件）
  - 负责键盘输入捕获
  - 负责输出候选热键组合
  - 负责处理 `Return` / `Esc` / 失焦事件
  - 不直接负责全局热键注册

- `ScreenshotHotKey`
  - 从“预设集合”扩为“真实热键模型”
  - 负责持久化值、显示值、键码与修饰键表达

- `GlobalHotKeyService`
  - 继续只负责注册与更新全局热键
  - 不承担设置页输入录制逻辑

也就是说，
“录制热键”和“注册热键”是两层职责，
本轮不把它们混在同一个控件里。

### 7. 数据存储

当前截图热键存储值是固定预设字符串，
只能表达少量内置选项。

本轮需要改为可表达任意：

- `keyCode`
- `modifiers`

的稳定序列化格式。

建议要求：

- 同一组合能稳定序列化与反序列化
- 能作为 `AppStorage` 持久化值使用
- 默认值仍然保留当前截图默认热键

本轮不要求把存储格式设计成未来多动作热键系统的通用协议，
只要求它足够清晰、足够稳定、足够满足当前截图热键这一项。

### 8. 范围控制

为了避免第一版复杂度失控，
本轮明确不做：

- 快捷键冲突详情列表
- 多个截图动作分别配置热键
- 历史热键记录
- 单独的热键录制弹窗
- 只有修饰键的特殊支持
- 鼠标按键或组合手势热键

后续如果需要扩展多动作热键系统，
应作为独立 Sprint 继续设计。

### 9. 错误处理与稳定性原则

本轮不把“用户输入无效组合”视为崩溃或异常场景。

最低要求：

- 只有修饰键时不能确认成功
- 注册失败时必须恢复旧热键
- 任何取消路径都必须恢复旧热键
- 失焦取消与 `Esc` 取消行为保持一致

如果无法成功注册新热键，
应用必须保持旧热键继续可用。

---

## 验收标准

1. 用户进入 `Settings` 后，可看到“截图快捷键”对应的可点击编辑框，而不是预设菜单。
2. 点击编辑框后，进入热键编辑模式。
3. 用户输入 `Command + A` 时，编辑框可实时显示该组合。
4. 用户输入 `Command + Shift + 8`、`Control + Option + F5`、`Command + ↑` 等组合时，编辑框可正确显示。
5. 用户只按修饰键时，不能直接确认为有效热键。
6. 用户按 `Return` 后，若组合有效且注册成功，新热键立即生效。
7. 用户按 `Return` 后，若注册失败，界面恢复旧热键并给出失败提示。
8. 用户按 `Esc` 后，会取消编辑并恢复旧热键。
9. 用户点击编辑框外部后，会取消编辑并恢复旧热键。
10. 保存目录配置与其他现有设置页行为保持正常。

---

## 实现建议

建议实现顺序：

1. 先扩展 `ScreenshotHotKey`，让它能表达任意自定义组合，而不是仅识别预设值。
2. 再补一个最小热键录制控件，先完成键盘捕获与组合显示。
3. 然后把 `SettingsView` 从 `Picker` 改为编辑框交互。
4. 最后接入现有 `GlobalHotKeyService.updateHotKey(...)` 完成注册、失败回退与提示。

当前项目没有独立测试工程，
本轮验证以：

- `./scripts/build.sh`
- `Settings` 页面人工交互验证
- 热键修改后的真实触发验证

为主。
