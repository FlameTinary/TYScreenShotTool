# 需求文档：长截图预览窗口布局优化

## 1. 背景

当前长截图模式下，长截图预览窗口的位置是根据**截图区域到屏幕边缘的剩余空间**来判断的。

现有逻辑大致如下：

* 获取当前长截图的截图区域 `selectionRect`。
* 判断 `selectionRect` 左边线到屏幕左边缘的距离。
* 判断 `selectionRect` 右边线到屏幕右边缘的距离。
* 哪边剩余空间更大，长截图预览窗口就显示在哪边。
* 预览窗口宽度不能超过截图区域边线到屏幕边缘的距离。
* 预览窗口高度不能超过当前屏幕高度。

这个逻辑在截图区域比较宽时基本可用，但在截图区域比较窄、工具栏比截图区域更宽的情况下，会出现预览窗口遮挡工具栏的问题。

---

## 2. 当前问题

在长截图模式下，如果截图区域较窄，长截图工具栏位于截图区域下方，此时工具栏的宽度可能明显大于截图区域宽度。

当前预览窗口只根据截图区域边线计算位置，因此会出现以下问题：

* 预览窗口没有遮挡截图区域本身。
* 但是预览窗口会压到长截图工具栏上。
* 工具栏上的按钮会被预览窗口遮挡。
* 用户在点击工具栏按钮、Hover 按钮、查看 Tooltip 时都会受到影响。

也就是说，当前布局只考虑了：

```text
selectionRect
```

但实际需要避让的是：

```text
selectionRect + longCaptureToolbarRect
```

---

## 3. 需求目标

长截图预览窗口的位置和尺寸计算，需要从：

```text
只避让截图区域
```

升级为：

```text
同时避让截图区域和长截图工具栏
```

核心目标：

* 预览窗口不能遮挡截图区域。
* 预览窗口尽量不能遮挡长截图工具栏。
* 预览窗口不能遮挡工具栏按钮。
* 当工具栏比截图区域更宽时，应以工具栏边界作为避让边界。
* 当截图区域比工具栏更宽时，应以截图区域边界作为避让边界。
* 预览窗口宽度需要有最大值，不能因为剩余空间很大而被撑得过宽。
* 预览窗口宽度需要有最小值，不能因为剩余空间很小而被压缩到不可用。
* 如果左右两侧都无法放下最小宽度，则选择空间更大的一侧，按最小宽度显示完整预览窗口。
* 不需要新增 Compact Preview 模式。
* 普通截图模式不应受到影响。

---

## 4. 核心布局规则

### 4.1 避让区域计算规则

预览窗口不应该只基于 `selectionRect` 判断左右空间。

需要同时获取：

```swift
selectionRect
toolbarRect
```

然后计算合并后的占用区域：

```swift
let occupiedRect = selectionRect.union(toolbarRect)
```

建议再加入安全间距：

```swift
let avoidRect = occupiedRect.insetBy(
    dx: -scrollingPreviewSpacing,
    dy: -scrollingPreviewSpacing
)
```

后续所有左右空间判断、预览窗口最大宽度计算、预览窗口 x 坐标计算，都应该基于 `occupiedRect` 或 `avoidRect`，而不是只基于 `selectionRect`。

---

### 4.2 坐标系要求

`selectionRect` 和 `toolbarRect` 必须转换到同一个坐标系后再计算。

不能混用：

* View 坐标
* Window 坐标
* Screen 坐标

如果当前预览窗口布局使用的是 screen coordinate，那么：

```swift
selectionRect
toolbarRect
screenFrame
```

都应该统一到 screen coordinate。

如果当前布局使用的是 overlay window coordinate，那么三者都应该统一到 overlay window coordinate。

重点要求：

* 不要直接拿 toolbar 的 local frame 去和 screen frame 比较。
* 不要错误使用 `NSScreen.main`。
* 多显示器场景下，应基于当前截图所在屏幕计算。
* 预览窗口不能跑到其他显示器。
* 预览窗口不能跨屏显示。

---

## 5. 预览窗口宽度规则

长截图预览窗口宽度需要增加最大值和最小值限制。

建议增加类似常量：

```swift
private let scrollingPreviewMinWidth: CGFloat = 160
private let scrollingPreviewMaxWidth: CGFloat = 280
private let scrollingPreviewSpacing: CGFloat = 12
```

具体数值可以根据当前 UI 微调，但必须保留以下概念：

```text
最小宽度 minWidth
最大宽度 maxWidth
间距 spacing
```

---

### 5.1 可用空间大于最大宽度

如果选中一侧的可用空间大于最大宽度：

```swift
availableWidth >= scrollingPreviewMaxWidth
```

则预览窗口宽度固定为最大值：

```swift
previewWidth = scrollingPreviewMaxWidth
```

目的：

* 避免预览窗口被撑得过宽。
* 保持视觉稳定。
* 保持长截图预览窗口在一个合理尺寸范围内。

---

### 5.2 可用空间在最小值和最大值之间

如果选中一侧的可用空间介于最小值和最大值之间：

```swift
scrollingPreviewMinWidth <= availableWidth < scrollingPreviewMaxWidth
```

则预览窗口宽度等于可用空间：

```swift
previewWidth = availableWidth
```

目的：

* 在空间有限但可用时，预览窗口可以适度压缩。
* 但不会小于最小可用宽度。

---

### 5.3 左右空间都小于最小宽度

如果左右两侧都放不下最小宽度：

```swift
leftAvailableWidth < scrollingPreviewMinWidth
rightAvailableWidth < scrollingPreviewMinWidth
```

此时不要进入 Compact Preview 模式。

当前需求是：

* 仍然显示完整预览窗口。
* 选择空间更大的一侧。
* 强制使用最小宽度显示：

```swift
previewWidth = scrollingPreviewMinWidth
```

这种情况下允许预览窗口覆盖截图区域的一小部分。

原因：

* 这是极端窄空间场景。
* 用户此时仍然需要看到完整预览窗口。
* 引入 Compact Preview 会增加交互复杂度。
* 预览窗口遮挡截图区域边缘的一小部分可以接受。
* 但仍然要尽量避免遮挡长截图工具栏。

---

## 6. 左右位置选择规则

### 6.1 计算左右可用空间

基于合并后的避让区域计算左右空间：

```swift
let occupiedRect = selectionRect.union(toolbarRect)

let avoidRect = occupiedRect.insetBy(
    dx: -scrollingPreviewSpacing,
    dy: -scrollingPreviewSpacing
)

let leftAvailableWidth = avoidRect.minX - screenFrame.minX
let rightAvailableWidth = screenFrame.maxX - avoidRect.maxX
```

---

### 6.2 判断左右是否能正常放置

```swift
let canPlaceLeft = leftAvailableWidth >= scrollingPreviewMinWidth
let canPlaceRight = rightAvailableWidth >= scrollingPreviewMinWidth
```

---

### 6.3 两侧都能放

如果左右两侧都能放下最小宽度：

```swift
canPlaceLeft == true
canPlaceRight == true
```

则选择空间更大的一侧：

```swift
placeOnRight = rightAvailableWidth >= leftAvailableWidth
```

预览窗口宽度为：

```swift
previewWidth = min(scrollingPreviewMaxWidth, selectedAvailableWidth)
```

---

### 6.4 只有右侧能放

如果只有右侧能放：

```swift
canPlaceRight == true
canPlaceLeft == false
```

则放右侧。

```swift
placeOnRight = true
previewWidth = min(scrollingPreviewMaxWidth, rightAvailableWidth)
```

---

### 6.5 只有左侧能放

如果只有左侧能放：

```swift
canPlaceLeft == true
canPlaceRight == false
```

则放左侧。

```swift
placeOnRight = false
previewWidth = min(scrollingPreviewMaxWidth, leftAvailableWidth)
```

---

### 6.6 左右两侧都放不下最小宽度

如果左右两侧都小于最小宽度：

```swift
canPlaceLeft == false
canPlaceRight == false
```

则选择空间更大的一侧：

```swift
placeOnRight = rightAvailableWidth >= leftAvailableWidth
```

并强制使用最小宽度：

```swift
previewWidth = scrollingPreviewMinWidth
```

这种情况下允许预览窗口向截图区域方向覆盖一部分，但不能超出当前屏幕。

---

## 7. 推荐实现流程

建议使用类似下面的决策流程：

```swift
let occupiedRect = selectionRect.union(toolbarRect)

let avoidRect = occupiedRect.insetBy(
    dx: -scrollingPreviewSpacing,
    dy: -scrollingPreviewSpacing
)

let leftAvailableWidth = avoidRect.minX - screenFrame.minX
let rightAvailableWidth = screenFrame.maxX - avoidRect.maxX

let canPlaceLeft = leftAvailableWidth >= scrollingPreviewMinWidth
let canPlaceRight = rightAvailableWidth >= scrollingPreviewMinWidth

let placeOnRight: Bool
let selectedAvailableWidth: CGFloat

if canPlaceLeft && canPlaceRight {
    // 两侧都能放，选择空间更大的一侧
    placeOnRight = rightAvailableWidth >= leftAvailableWidth
    selectedAvailableWidth = placeOnRight ? rightAvailableWidth : leftAvailableWidth
} else if canPlaceRight {
    // 只有右侧能放
    placeOnRight = true
    selectedAvailableWidth = rightAvailableWidth
} else if canPlaceLeft {
    // 只有左侧能放
    placeOnRight = false
    selectedAvailableWidth = leftAvailableWidth
} else {
    // 左右都放不下最小宽度
    // 选择空间更大的一侧，并使用最小宽度
    placeOnRight = rightAvailableWidth >= leftAvailableWidth
    selectedAvailableWidth = max(leftAvailableWidth, rightAvailableWidth)
}

let previewWidth: CGFloat

if selectedAvailableWidth >= scrollingPreviewMinWidth {
    previewWidth = min(scrollingPreviewMaxWidth, selectedAvailableWidth)
} else {
    previewWidth = scrollingPreviewMinWidth
}
```

## 8. 预览窗口 X 坐标计算规则

### 8.1 放在右侧时

正常情况下，右侧显示应基于 `avoidRect.maxX`：

```swift
let desiredPreviewX = avoidRect.maxX + scrollingPreviewSpacing
```

但需要确保预览窗口不超出屏幕右边界：

```swift
let previewX = min(
    desiredPreviewX,
    screenFrame.maxX - previewWidth
)
```

如果右侧空间不足但仍选择右侧，预览窗口会向左覆盖截图区域的一部分。

这是允许的。

---

### 8.2 放在左侧时

正常情况下，左侧显示应基于 `avoidRect.minX`：

```swift
let desiredPreviewX = avoidRect.minX - scrollingPreviewSpacing - previewWidth
```

但需要确保预览窗口不超出屏幕左边界：

```swift
let previewX = max(
    desiredPreviewX,
    screenFrame.minX
)
```

如果左侧空间不足但仍选择左侧，预览窗口会向右覆盖截图区域的一部分。

这是允许的。

---

## 9. 预览窗口高度规则

当前需求主要调整宽度和左右布局。

高度可以先沿用现有规则：

* 不能超过当前屏幕高度。
* 不能跨出当前屏幕。
* 如果已有最大高度限制，可以继续保留。
* 如果预览窗口高度较高，需要确保它仍然在当前 screenFrame 内。

如果当前逻辑已经稳定，不需要额外重构高度部分。

## 11. 修复要求

1. 不要通过提高工具栏层级来绕过问题。
2. 不要通过隐藏预览窗口来绕过问题。
3. 不要通过移动工具栏来绕过问题。
4. 根本原因是预览窗口避让区域计算不完整，需要修复布局计算逻辑。
5. 预览窗口应该避让 `selectionRect.union(toolbarRect)`。
6. 后续左右空间判断、宽度计算、x 坐标计算，都应该基于合并后的避让区域。
7. 预览窗口必须有最大宽度。
8. 预览窗口必须有最小宽度。
9. 不需要新增 Compact Preview 模式。
10. 左右都放不下最小宽度时，选择空间更大的一侧，以最小宽度显示完整预览窗口。
11. 极端情况下允许预览窗口覆盖截图区域的一部分。
12. 仍然要尽量避免遮挡长截图工具栏。
13. 预览窗口不能超出当前屏幕。
14. 多显示器场景下，必须基于当前截图所在屏幕计算。
15. 普通截图模式不能受影响。

## 12. 验收标准

### 场景 1：截图区域较宽

操作：

* 进入长截图模式。
* 选择一个较宽的截图区域。

期望：

* 预览窗口仍然显示在剩余空间更大的一侧。
* 不遮挡截图区域。
* 不遮挡长截图工具栏。
* 行为与现有逻辑基本一致。

---

### 场景 2：截图区域较窄，工具栏比截图区域宽

操作：

* 进入长截图模式。
* 选择一个比较窄的截图区域。
* 让长截图工具栏宽度明显大于截图区域宽度。

期望：

* 预览窗口不能只根据截图区域边线摆放。
* 预览窗口应基于 `selectionRect.union(toolbarRect)` 计算位置。
* 预览窗口不能压到工具栏按钮上。
* 工具栏按钮仍然可以正常点击。
* 工具栏按钮 Tooltip 不应被预览窗口遮挡。

---

### 场景 3：右侧空间很大

操作：

* 选择一个偏左的截图区域，使右侧空间很大。

期望：

* 预览窗口显示在右侧。
* 预览窗口宽度不超过最大宽度。
* 不会因为右侧空间大而变得特别宽。

---

### 场景 4：左侧空间很大

操作：

* 选择一个偏右的截图区域，使左侧空间很大。

期望：

* 预览窗口显示在左侧。
* 预览窗口宽度不超过最大宽度。
* 不会因为左侧空间大而变得特别宽。

---

### 场景 5：一侧空间在最小值和最大值之间

操作：

* 调整截图区域位置，让某一侧可用空间介于最小宽度和最大宽度之间。

期望：

* 预览窗口显示在可用的一侧。
* 预览窗口宽度等于当前可用空间。
* 预览窗口不会小于最小宽度。
* 预览窗口不会超过最大宽度。

---

### 场景 6：左右两侧都小于最小宽度

操作：

* 选择一个极端位置或极端宽度，使左右两侧剩余空间都小于最小宽度。

期望：

* 不进入 Compact Preview 模式。
* 选择剩余空间更大的一侧。
* 使用最小宽度显示完整预览窗口。
* 允许预览窗口覆盖截图区域的一小部分。
* 预览窗口不能超出当前屏幕。
* 尽量不要遮挡长截图工具栏。

---

### 场景 7：多显示器

操作：

* 在副屏进入长截图模式。
* 选择不同宽度和不同位置的截图区域。

期望：

* 预览窗口应该出现在当前截图所在屏幕内。
* 不应该跑到主屏。
* 不应该跨屏显示。
* 不应该遮挡当前屏幕上的长截图工具栏。
* 所有坐标计算都基于当前截图所在屏幕。

---

### 场景 8：普通截图模式回归验证

操作：

* 进入普通截图模式。
* 使用普通截图工具栏。
* 验证普通截图已有功能。

期望：

* 普通截图工具栏不受影响。
* 普通截图 Tooltip 不受影响。
* 普通截图区域选择不受影响。
* 普通截图保存、复制、OCR、AI 等按钮逻辑不受影响。

---

## 13. 最终目标

长截图预览窗口布局规则需要调整为：

```text
先基于 selectionRect + toolbarRect 计算避让区域；
再判断左右可用空间；
预览窗口宽度限制在 minWidth ~ maxWidth 之间；
如果左右都小于 minWidth，则选择空间更大的一侧，用 minWidth 显示完整预览窗口；
极端情况下允许覆盖截图区域一部分，但不能超出屏幕，且尽量不遮挡工具栏。
```

核心实现思路：

```swift
let occupiedRect = selectionRect.union(toolbarRect)
```

后续所有布局计算都应该围绕这个合并后的 `occupiedRect` 展开，而不是只围绕 `selectionRect` 展开。

本次不需要实现 Compact Preview 模式。
